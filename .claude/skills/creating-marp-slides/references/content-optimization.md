# コンテンツ最適化

項目数やコード行数だけで見切れを判定せず、使用テーマ・文字サイズ・画像・改行を含む実際の表示で判断する。

- 伝えたい要点を保ち、情報が多い場合はスライドを分割する。
- コードは説明に必要な範囲を残す。長い行や大きな表は横方向の見切れも確認する。
- 数式は読みやすさを優先し、ブロック数式の高さも含めて配置する。
- 文字を極端に小さくして収める前に、文章の短縮や構成の変更を検討する。

## 表示確認

`bun run preview` で対象を開き、画像・文字の重なり・見切れ・コントラストを確認する。
ブラウザ操作ツールがあれば各スライドのスクリーンショットを使う。
代わりに Marp CLI の画像出力を使う場合は、`--images png` で全ページを出力できる:

```bash
mkdir -p dist/review
bun run -- marp slides/example.md --images png -o dist/review/example.png --allow-local-files
```

画像出力にも対応ブラウザが必要。生成した各ページを実際に開いて確認する。
最終成果物が PDF/PPTX の場合は、その成果物も確認する。
表示確認ができない環境では、テキスト上の懸念と未検証の範囲を明記する。
